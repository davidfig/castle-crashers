# Agent notes

- **Other agents may be editing this tree at the same time; heed the heads-ups.** Hooks in `.claude/settings.json` track every session's prompt and edited files automatically (nothing to register). At session start you're told who else is active; before you edit a file another live session touched in the last 30 minutes, you get a warning. When you do, re-read the file, keep the edit narrow, and never revert lines you didn't write. `node tools/agent-work.mjs list` shows everything in flight.
- **Never use `git stash`** (including `git stash -u`, `pop`, `drop`). Multiple agents often work on the same branch and working tree at once, so stashing sweeps up, hides, or loses other agents' in-progress changes. To inspect a clean state, use `git diff`/`git show` or a worktree instead.
- **Keep code in small, well-named files.** Organize by functionality: one file, one clear job, named for what it does. When a file grows large or mixes varied functionality, split it into separate files. Place files in subdirectories that group related functionality, and nest directories hierarchically as needed (e.g. `data/heroes/`, `render/…`) rather than piling files into one flat folder. Update imports and docs when you move or split files.
- **We use pnpm, not npm.** Run scripts as `pnpm <script>` (`pnpm dev`, `pnpm test`, `pnpm typecheck`, `pnpm kill`...) and install with `pnpm add` / `pnpm install`. Commands written as `npm run X` in older docs and comments mean `pnpm X`.
- **On `main`, use the user's dev server; don't start your own.** The user keeps a dev server (`pnpm dev`, port 4000) running off `main`. Agents working on `main` test against it, e.g. `http://localhost:4000/?mute=1`. If it isn't running, stop and tell the user so they can start it. Don't launch one yourself (no `pnpm dev` and no `preview_start` for the dev server). Agents in other worktrees or branches are not covered by this rule.
- **A run is one road** (`docs/21-the-road.md`): a single sim from the starting town to the last boss, levels, road scenes, camps and crossroads laid end to end (`src/sim/gen/road.ts`). There are no per-level sims, stores or carry any more. Anything the party stops at (a camp, a scene, a town) is a *calm place* with ground of its own, and the road grows around it so no horde can reach it: add a new one to `layoutRoad`, never clear encounters or hold spawns. The run is saved as it goes (`campaign/runSave.ts`), so everything that decides play must live in `GameState` (the snapshot test fails otherwise). Look at any stretch with `?seed=N&levels=15&at=K`.
- **Test the game muted.** When launching the game in a browser to test or screenshot it, add `?mute=1` to the URL (combine with other dev params, e.g. `?mute=1&seed=5&bots=3`). It keeps sound and music off for that page load without changing the player's remembered N / M toggles.
- **Game decisions live in `docs/`, not here.** Gameplay rules, design limits and per-system constraints are in the docs; read the relevant one before changing a system, and record new decisions there (or in `docs/decisions/`), not in this file. Start at `docs/README.md`. Pointers:
  - Combat, mobs entering and leaving the play area (over the hill / behind the ridge): `docs/03-gameplay-combat.md`
  - Generated enemies (`MOBS` vs `CLASSIC_MOBS`, tuning, balance probe): `docs/15-random-bestiary.md`
  - Generated scenery, biomes and the road: `docs/17-generated-scenery.md`, `docs/21-the-road.md`
  - Generated people: `docs/19-generated-humans.md`; generated heroes (class kit always drawn): `docs/20-generated-heroes.md`
  - Settled choices and their reasons: `docs/decisions/`; undecided things: `docs/open-questions.md`
