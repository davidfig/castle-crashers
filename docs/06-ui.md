# 06 — UI

## Principle: UI never blocks

During a run there are **no pause menus, no modal dialogs, no full-screen inventories**. The game keeps simulating while any UI is visible. UI belongs to a character, appears **near that character**, and goes away by itself or by simply continuing to play.

Corollary: because the world never stops, each UI element must be (1) glanceable, (2) operable in under a second, (3) safe to ignore.

Pause is allowed *only* in non-run contexts (hub, settings) and, in single-player, an explicit Pause button that opens a minimal overlay (the one allowed exception). In multiplayer, there is **no pause**; settings are accessed at rest rooms.

## UI layers

| Layer | Examples | Anchor |
|---|---|---|
| **Character HUD** | HP/resource bar, level pip, status icons, cooldown pips | Above/below the character, small, follows them |
| **Contextual prompts** | "Pick up *Frost Brand* ▲▼ stats", interact hints | Near the character, at the object |
| **Swap ring** | Quick switch of abilities/items | Around the character while Swap held |
| **Level-up strip** | 3 upgrade cards | Beside/above the character |
| **Toasts** | "P2 gave you …", achievements | Over the head, brief |
| **Party strip** | Tiny overview of all players' HP/level | Screen edge, optional |
| **World UI** | Damage numbers, boss HP bar, room goal | World/screen overlay; non-interactive |

All are drawn through the sprite batcher with the bitmap font ([02](02-rendering.md)) and a shared UI atlas.

## Per-character anchoring

- Each player has a **UI anchor** at their screen position (clamped to stay on-screen).
- Elements stack in a small layout box: they avoid overlapping *other* players' boxes with a cheap relaxation pass (push apart on screen, deterministic order by player index).
- UI scales in whole pixels with the game; a user "UI size" setting selects 1× / 1.5× UI text variants by swapping to a larger bitmap font (no fractional scaling).
- Player colors and icon shapes identify ownership (color + glyph for accessibility).

## Swap ring

Hold **Swap** → a radial of up to 6–8 entries opens around your character. The game continues (optionally with a *subtle* personal slow-mo, see below — never a global pause).

- **Direction select:** move the stick/direction to highlight, release Swap to commit. Mouse/keyboard: 1–8 keys or direction keys.
- **Two pages** (tap Swap to toggle): *Abilities* (bench ↔ active slots) and *Items* (backpack/belt/equipment; drop and hand-over).
- **Hand-over target:** while the ring is on an item, a directional gesture toward an ally highlights them with an arrow; release to hand over (see [05](05-items-trading.md)).
- **Personal time dilation (optional, off by default):** the *sim* may apply a per-player 0.25× speed to the opening player only while the ring is open. It's deterministic (a sim-level status) and keeps combat from feeling frozen. Design target: ring selection must be completable in < 0.7 s with muscle memory.

## Level-up strip

On level-up, a 3-card strip appears by your character with a pop sound and a ring flash.

- Select with the face buttons / number keys mapped left/middle/right, or by direction + Swap.
- Unselected strips **collapse into a pulsing badge** on your HUD after ~6 s; the offer is not lost and can be reopened any time (with Swap long-press or a dedicated button).
- Each card: icon, 2-word name, one-line effect, rarity border, synergy-tag glyphs.

## Item prompts

When near a pickup: a floating tag shows name, rarity color, and **delta vs. equipped** (green ▲ / red ▼ per stat), plus a corner icon showing whether it suits a teammate's class. Interact = pick up. If two players stand near the same item, each sees their own comparison.

## Feedback & juice

- Damage numbers (pooled, bitmap font), crit variants, status text.
- Rarity-colored beams and sparkles on drops.
- Controller rumble hooks for hits and revives (when supported).
- Cooldowns shown as radial wipes on the HUD pips.

## Hub / meta UI (can block)

The hub (between runs) is allowed menus: class tree viewer, codex, settings, modifier selection. Even here, prefer **diegetic** interactions (walk to the Renown Altar, the Armory, the Notice Board) with controller-friendly menus. Class tree UI: pannable node graph, locked/available/owned states, cost shown, focus caps for active branches.

## Accessibility

- Color + shape + icon redundancy for rarity, teams, and statuses.
- Adjustable UI scale, screen-shake and flash intensity, hold-vs-toggle for Swap.
- Colorblind palettes for rarity/element indicators.
- Fully remappable controls.

## Implementation notes

- UI state that affects gameplay (ring open, selection made, item handed over) is expressed as **input actions** into the sim, so it's deterministic and net-ready. Purely visual state (animations, layout) lives in `ui/` and is not part of sim state.
- A `UIModel` is derived from `GameState` each frame (what each player can currently do); the UI renders and animates that model.
